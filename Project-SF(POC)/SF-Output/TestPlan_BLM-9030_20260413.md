# 1. Objective

This document outlines the **test plan for BLM-9030 – Unified Validation Framework for Opportunity Fields Required During Bid Creation and Later Stages** in the Salesforce Application.

The objective is to ensure that **all validation rules work as expected** for the target audience, including Opportunity Owners and Bid Managers who manage Opportunities through the bid lifecycle. The validation framework must guarantee that governance-relevant data is always complete, reliable, and cannot be removed in non-permitted stages.

---

# 2. Scope

The scope of this test plan includes:

### Features to be Tested
- **Case 1 Validation Rules:** Required fields on Bid Creation stage transition
- **Case 2 Validation Rules:** No clearing of fields in Bid stages
- **Case 3 Validation Rules:** No clearing after Closed Won/Lost
- Stage transition behavior (Prospecting → Bid Creation → Negotiation → Awarded → Closed)
- Field-level error message display (English and German)
- New Opportunity creation bypass behavior (BLM-8973 integration)
- Deprecated rule handling (zdelete_ prefix)
- Amount threshold removal for Expected Submission Date

### Fields in Scope
1. Nearshore / Offshore
2. (Expected) Contract Type
3. Bid Manager
4. Surveillance Director
5. Bid / No Bid Decision
6. Pre-Sales Risk Level
7. Expected Submission Date
8. Project Margin (%)

### Types of Testing
- Functional Testing  
- Negative Testing  
- Boundary Value Testing
- Regression Testing
- Localization Testing (EN/DE)
- Integration Testing

### Environments
- Salesforce Sandbox
- Salesforce Developer Edition
- Multiple browsers (Chrome, Firefox, Edge, Safari)

### Evaluation Criteria
- All 18 validation rules function correctly
- Error messages display at field level
- No conflicts with existing validation rules
- Zero critical defects at release

### Team Roles and Responsibilities
- Test Lead: Test planning and coordination
- Test Engineers: Test case execution and defect logging
- Salesforce Developers: Defect resolution
- Business Analyst: Requirements clarification
- Stakeholders: Sign-off approval

# 3. Inclusions

## Introduction
This test plan covers the comprehensive testing of the Unified Validation Framework implemented for Opportunity stage transitions and field governance in Salesforce.

## Test Objectives
- Verify all Case 1 validation rules trigger correctly during stage transitions
- Verify all Case 2 validation rules prevent field clearing in Bid stages
- Verify all Case 3 validation rules prevent field clearing after Closed stages
- Validate exact error messages in English and German
- Confirm no conflicts with Editable_Fields_if_Closed rule
- Verify deprecated rules are renamed with zdelete_ prefix
- Confirm amount threshold removal for Expected Submission Date
- Ensure new Opportunity creation shows BLM-8973 warning (not Case 1-3 errors)

# 6. Defect Reporting Procedure

### Criteria for Identifying Defects
- Validation rule does not trigger when expected
- Validation rule triggers incorrectly
- Error message text mismatch (EN or DE)
- Error not displayed at field level
- Conflict with other validation rules
- Stage transition blocked incorrectly
- Stage transition allowed incorrectly

### Severity Levels
| Severity | Description |
|----------|-------------|
| Critical | Validation completely bypassed; governance data can be deleted |
| High | Incorrect error message or wrong field association |
| Medium | Localization issues; minor UX problems |
| Low | Cosmetic issues; documentation errors |

### Steps for Reporting Defects
1. Use JIRA defect template
2. Include: Test Case ID, Steps to Reproduce, Expected vs Actual Result
3. Attach screenshots of validation errors
4. Specify Stage, Field, and Language tested
5. Assign severity and priority

### Tracking Tools
- JIRA – Defect Tracking
- Confluence – Test Documentation

### Communication Channels
- Daily stand-up meetings
- JIRA dashboard updates
- Email notifications for critical defects

## Step 2: Testing Procedure

### Smoke Testing
Verify core validation rules after deployment:
- [ ] Case 1: At least one field validation on stage transition
- [ ] Case 2: At least one field clearing prevention
- [ ] Case 3: Surveillance Director clearing after close
- [ ] New Opportunity creation warning

### Functional Testing
Execute all test cases covering:
- All 8 fields × Case 1 rules = 8 validations
- All 8 fields × Case 2 rules = 8 validations
- 2 fields × Case 3 rules = 2 validations
- Stage combinations (Prospecting → Bid Creation, Qualification → Negotiation, etc.)

### Negative Testing
- Attempt to bypass validations
- Attempt to clear protected fields
- Attempt direct stage jumps

### Regression Testing
- Verify Editable_Fields_if_Closed rule still functions
- Verify BLM-8973 creation warning still functions
- Verify no duplicate errors on same action

### Localization Testing
- Execute key test cases in German language setting
- Verify exact German error messages per specification
