# Feature Context: BLM-9030 Unified Validation Framework for Opportunity Fields Required During Bid Creation and Later Stages

## Overview
To address functional gaps and ensure alignment across the Opportunity lifecycle, we introduce a unified validation framework based on three governance cases. Each case follows a single naming logic, uniform error wording, and predictable validation behaviour across all affected fields. All validation rules display their error directly on the corresponding field to maximize clarity. The existing validation rules will be replaced and renamed with the prefix `zdelete_` to mark them for deprecation.

## User Stories
- As an **Opportunity Owner / Bid Manager**, I want **mandatory information to be validated consistently during stage transitions and field edits** so that **governance‑relevant data is always complete, reliable, and cannot be removed in non‑permitted stages.**

## Acceptance Criteria
- [ ] All eight fields relevant for the transition into Bid Creation and later stages - Nearshore / Offshore, Expected Contract Type, Bid Manager, Surveillance Director, Bid / No Bid Decision, Pre-Sales Risk Level, Expected Submission Date and Project Margin (%) - require a non empty value when an Opportunity is moved from Prospecting or Qualification into Bid Creation, Negotiation, Awarded or Closed Won, as defined in the Case 1 table in the description.
- [ ] None of the eight fields listed above can be cleared while the Opportunity is in Bid Creation, Negotiation or Awarded, although updates to existing values remain possible. This behaviour is implemented consistently for all fields as described in the Case 2 table in the description.
- [ ] The fields Surveillance Director and Project Margin (%) cannot be cleared after an Opportunity has reached Closed Won or Closed Lost, while still allowing modifications to the existing values, as specified in the Case 3 table in the description.
- [ ] All validation rules referenced in the Case 1, Case 2 and Case 3 tables use the exact English and German error messages defined in those tables and display the error at the respective field level.
- [ ] All validation rules use the naming conventions shown in the Case 1, Case 2 and Case 3 tables and follow the unified structure described in the story.
- [ ] The existing validation rules listed in the Additional Information section—Nearshore_Offshore_before_Bid_Creation, Expected_Contract_Type_Bid_Creation, Bid_Manager_Qualification, Surveillance_Director, Set_Bid_to_change_stage, Pre_Sales_Risk_Level_before_Bid_MGMT, Expected_Submission_Date and Project_Margin_required_after_bid_creati—have been replaced, re implemented or supplemented as required, and all replaced or reworked rules have been renamed using the prefix zdelete_* for later removal.
- [ ] The amount threshold of 199,999 EUR for the Expected Submission Date validation has been fully removed so that validation behaviour aligns with the Case 1 and Case 2 definitions.
- [ ] When creating a new Opportunity and the user selects "Bid Creation" or any later stage only the validation rule delivered with SFSUPPORTDE_BLM‑8973 shall trigger while all validation rules introduced with this ticket (Cases 1–3) must remain suppressed during creation.
- [ ] No validation rule created or adapted as part of this story conflicts with other existing logic, in particular the rule Editable_Fields_if_Closed, and all fields behave consistently and predictably throughout the entire Opportunity lifecycle according to the definitions in the description.

## Validation Rules
### Case 1: Required Fields for Bid Creation and Subsequent Stages
Ensures all eight fields contain a value when moving from Prospecting/Qualification to Bid Creation, Negotiation, Awarded, or Closed Won.
| Field | Rule Name |
|---|---|
| Nearshore / Offshore | NearshoreOffshore_ReqOnBidCreation |
| (Expected) Contract Type | ExpectedContractType_ReqOnBidCreation |
| Bid Manager | BidManager_ReqOnBidCreation |
| Surveillance Director | SurveillanceDirector_ReqOnBidCreation |
| Bid / No Bid Decision | BidDecision_ReqOnBidCreation |
| Pre-Sales Risk Level | PreSalesRiskLevel_ReqOnBidCreation |
| Expected Submission Date | ExpectedSubmissionDate_ReqOnBidCreation |
| Project Margin | ProjectMargin_ReqOnBidCreation |

### Case 2: Prevent Clearing Fields in Bid Stages
Ensures none of the eight fields can be cleared while in Bid Creation, Negotiation, or Awarded.
| Field | Rule Name |
|---|---|
| Nearshore / Offshore | NearshoreOffshore_NoClearingInBidStages |
| Expected Contract Type | ExpectedContractType_NoClearingInBidStages |
| Bid Manager | BidManager_NoClearingInBidStages |
| Surveillance Director | SurveillanceDirector_NoClearingInBidStages |
| Bid / No Bid Decision | BidDecision_NoClearingInBidStages |
| Pre-Sales Risk Level | PreSalesRiskLevel_NoClearingInBidStages |
| Expected Submission Date | ExpectedSubmissionDate_NoClearingInBidStages |
| Project Margin | ProjectMargin_NoClearingInBidStages |

### Case 3: Prevent Clearing Fields After Opportunity is Closed
Ensures specific fields cannot be cleared after an Opportunity is Closed Won or Closed Lost.
| Field | Rule Name |
|---|---|
| Surveillance Director | SurveillanceDirector_NoClearingAfterClose |
| Project Margin | ProjectMargin_NoClearingAfterClose |

## Error Messages

| Case 1 | To move to the "Bid Creation" stage or any subsequent stage, a value in this field is required. | Für den Wechsel in die Phase „Angebotserstellung“ oder eine folgende Phase ist eine Angabe in diesem Feld erforderlich. |
| Case 2 | In the "Bid Creation", "Negotiation", and "Awarded" stages, a value in this field is required. | In den Phasen „Angebotserstellung“, „Verhandlung“ und „Mündliche Zusage“ ist eine Angabe in diesem Feld erforderlich. |
| Case 3 | After the Opportunity is closed, this field can be edited but must have a value. | Dieses Feld kann nach Abschluss der Opportunity bearbeitet werden, darf jedoch nicht leer bleiben. |
