## Note on Field Mapping

This test suite is a migration validation suite rather than a product feature suite, so it has no "User Story" reference. The **Reference & Status** column below therefore carries the test case **Priority** (Critical/High/Medium/Low) instead of a User Story ID, and each test's category/section takes the place of "Feature". The **Test Detail** column combines the source suite's Test Step and Test Action fields into a single bullet list (steps first, verification actions after), and the **Expected Outcome** column reflects the source suite's Expected Result field.

## Risks & Dependencies

### Dependencies
- Migration Team completes Phase 1 (Test Environment) migration and initial technical sanity checks before this suite is executed.
- Source (On-Premises) environment remains available/read-only for side-by-side comparison during test execution.
- Real values for all `<SOURCE_...>`/`<TARGET_...>`/`<CLOUD_USER>` placeholders are supplied by the Migration Team before execution.

- Xray Cloud compatibility issues could block traceability validation (Requirement -> Test -> Test Execution -> Defect).
- Broken or remapped links (Jira <-> Confluence, SharePoint, external) may be misclassified as defects if expected migration exceptions are not documented in advance.
- Incomplete or delayed source-environment count/report data may block Data Reconciliation test execution.
