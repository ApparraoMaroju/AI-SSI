# US-01: Assign LDAP User as On-call Participant

## 1. Requirement Title
Assign an LDAP-authenticated user as an on-call participant by linking them to alarm media (SMS/Pager).

---

## 2. Business Objective
- **Business Need:** On-call duty requires that personnel can be reached via SMS or pager when alarms occur. Before a user can be placed on any duty schedule, they must be registered as an on-call participant with at least one active alarm medium.
- **Value Delivered:** Ensures that alarm notifications are routed to real, contactable personnel, reducing the risk of missed critical infrastructure alarms.
- **Why It Exists:** The on-call system must know which devices (cell phone, pager) belong to which user so that alarm messages can be delivered correctly via the F24 eCall interface.

---

## 3. Detailed Requirement Description

### Confirmed Requirements
- An administrator can create an on-call participant by selecting an existing LDAP user.
- One or more alarm media (SMS or Pager) must be assigned to the on-call participant.
- Each alarm medium has an identification (unique, not editable after creation), a number (digits only), and a type (SMS or Pager).
- Multiple alarm media can be assigned to a single participant.
- Each alarm medium can be individually activated or deactivated.
- Only authenticated LDAP users or SSO-authenticated users can be assigned as on-call participants.

### Assumptions
- The LDAP user directory is available and synchronized with the on-call system.
- The administrator has the required authorization rights to manage on-call participants.
- At least one alarm medium must be active for the participant to receive alarms.

### Not Specified
- Maximum number of alarm media per participant.
- Whether an on-call participant can be deleted if they are assigned to active or future duty periods.
- Behaviour when an LDAP user account is disabled or removed from the directory.

---

## 4. User Story

**As an** administrator  
**I want** to assign an LDAP user as an on-call participant by linking their account to one or more alarm media (SMS/pager)  
**So that** the user can be contacted when on-call alarms are triggered for their assigned duty periods

---

## 5. Functional Scope
- Create a new on-call participant from an existing LDAP user
- Create alarm media with unique identification, number, and type (SMS/Pager)
- Assign one or more alarm media to the participant
- Activate or deactivate individual alarm media for the participant
- Display the list of assigned alarm media per participant
- Validate that alarm medium identification is unique
- Validate that alarm medium number contains only digits

---

## 6. Out of Scope
- LDAP user creation or management (handled externally)
- F24 eCall interface configuration
- On-call period assignment (covered in a separate user story)
- Alarm routing logic

---

## 7. Preconditions
- The LDAP user must exist and be authenticated
- The administrator must have authorization to manage on-call participants
- The alarm media configuration screen must be accessible

---

## 8. Trigger
- Administrator navigates to Configuration View → On-call Participants tab and initiates creation of a new on-call participant.

---

## 9. Main Success Flow
1. Administrator opens the Configuration View and selects the On-call Participants tab.
2. Administrator clicks "Create New On-call Participant."
3. System displays a list of available LDAP users.
4. Administrator selects an LDAP user.
5. Administrator creates or selects existing alarm media (entering identification, number, and type).
6. System validates that the alarm medium identification is unique and the number contains only digits.
7. Administrator assigns the alarm media to the participant.
8. Administrator activates the alarm media.
9. System saves the on-call participant with the linked alarm media.
10. System displays a confirmation and the updated participant list.

---

## 10. Alternate Flows

### AF-01: No Alarm Medium Assigned
- Administrator attempts to save an on-call participant without linking any alarm medium.
- **Expected:** System prevents saving or displays a warning indicating that at least one alarm medium is required.
- **Assumption:** The system enforces a minimum of one alarm medium per participant.

### AF-02: Duplicate Alarm Medium Identification
- Administrator enters an alarm medium identification that already exists.
- **Expected:** System displays a validation error stating the identification must be unique.

### AF-03: Invalid Alarm Medium Number
- Administrator enters non-numeric characters in the alarm medium number field.
- **Expected:** System displays a validation error stating only numbers are allowed.

### AF-04: All Alarm Media Deactivated
- Administrator deactivates all alarm media for an existing on-call participant.
- **Expected:** System allows deactivation but alarms will not be forwarded to this participant. A warning may be displayed.

### AF-05: LDAP User Not Found
- The LDAP user list is empty or the desired user is not available.
- **Expected:** Administrator cannot create the on-call participant. System may prompt to verify LDAP connectivity.

---

## 11. Acceptance Criteria

- GIVEN an authenticated administrator, WHEN they select an LDAP user and assign at least one alarm medium, THEN the on-call participant is created successfully.
- GIVEN an alarm medium identification, WHEN the identification already exists in the system, THEN the system displays a validation error and prevents saving.
- GIVEN an alarm medium number field, WHEN non-numeric characters are entered, THEN the system displays a validation error.
- GIVEN an on-call participant, WHEN multiple alarm media are assigned, THEN all assigned media are displayed in the participant's detail view.
- GIVEN an on-call participant, WHEN an individual alarm medium is deactivated, THEN alarms are no longer sent to that medium while other active media continue to receive alarms.
- System must not allow assignment of non-LDAP-authenticated users as on-call participants.
- Alarm medium identification must not be editable after initial creation.

---

## 12. Assumptions
1. LDAP directory is accessible and up-to-date.
2. At least one alarm medium must be linked for the participant to be functional.
3. The administrator role has full access to the on-call participant configuration screen.
4. Alarm medium identification uniqueness is enforced system-wide, not per participant.

# US-02: Assign On-call Participant to a Duty Period

## 1. Requirement Title
Assign an on-call participant to a duty period within a basic on-call plan for a specific region.

---

## 2. Business Objective
- **Business Need:** Each on-call duty period must have a designated participant responsible for responding to alarms. Without assignment, alarms for that period and region will not be forwarded.
- **Value Delivered:** Ensures continuous on-call coverage for all regions, preventing gaps in alarm response.
- **Why It Exists:** The on-call system uses duty period assignments to determine who receives alarm notifications at any given time.

---

## 3. Detailed Requirement Description

### Confirmed Requirements
- An on-call planner can assign an on-call participant to a period within a basic plan.
- A basic plan defines on-call duty for a specific time interval and region.
- Periods are typically one week long but can be split or merged.
- The system displays an info box with participant details when a period is selected.
- A warning is displayed when the assigned participant differs from the originally planned participant.
- An unassigned period means alarms will not be forwarded for that time range.

### Assumptions
- The on-call participant must already be configured with at least one active alarm medium.
- The on-call planner has authorization to assign participants to periods.

### Not Specified
- Whether the system prevents saving a period without an assigned participant or only warns.
- Whether a participant can be assigned to overlapping periods in the same region.

---

## 4. User Story

**As an** on-call planner  
**I want** to assign an on-call participant to a duty period within a basic plan  
**So that** alarms occurring during that period are forwarded to the correct person for the assigned region

---

## 5. Functional Scope
- Select a basic plan for a specific region
- View available periods within the plan
- Assign an on-call participant to a selected period
- Display participant details in the info box upon selection
- Display a warning when the assigned participant differs from the planned participant
- Save the assignment

---

## 6. Out of Scope
- Creation or deletion of basic plans
- Alarm forwarding logic
- Escalation configuration (covered in a separate user story)
- On-call participant creation

---

## 7. Preconditions
- A basic plan must exist for the target region and time interval.
- At least one on-call participant must be configured in the system.
- The on-call planner must have appropriate authorization rights.

---

## 8. Trigger
- On-call planner navigates to the Planning View and selects a period within a basic plan.

---

## 9. Main Success Flow
1. On-call planner opens the Planning View.
2. On-call planner selects a region and a basic plan.
3. System displays the periods within the basic plan.
4. On-call planner selects a specific period.
5. System displays the info box with current period details.
6. On-call planner selects an on-call participant from the available participant list.
7. System assigns the participant to the period.
8. System saves the assignment.
9. System updates the planning view to reflect the assignment.

---

## 10. Alternate Flows

### AF-01: Participant Differs from Planned
- On-call planner assigns a participant different from the originally planned participant.
- **Expected:** System displays a warning message upon saving. The assignment is still saved.

### AF-02: Period Left Unassigned
- On-call planner does not assign any participant to a period.
- **Expected:** The period remains unassigned. Alarms occurring during this period are not forwarded. The system may display a visual indicator for unassigned periods.

### AF-03: Participant Has Recorded Absence
- The selected participant has a recorded absence (vacation, sickness, etc.) during the period.
- **Expected:** System displays a warning but does not prevent the assignment.

### AF-04: Period Includes a Public Holiday
- The selected period includes a public holiday.
- **Expected:** System displays a warning indicating the holiday overlap.

### AF-05: Participant Assigned to Multiple Regions
- The same participant is assigned to periods in multiple regions simultaneously.
- **Expected:** System allows the assignment. Evaluation reports highlight this with orange color coding.

---

## 11. Acceptance Criteria

- GIVEN an on-call planner with appropriate authorization, WHEN they select a period and assign a participant, THEN the participant is saved against that period.
- GIVEN a period with an assigned participant, WHEN the period is selected, THEN the info box displays the participant's details (name, alarm media).
- GIVEN a period, WHEN the assigned participant differs from the originally planned participant, THEN the system displays a warning upon saving.
- GIVEN a period without an assigned participant, WHEN an alarm occurs during that period, THEN the system does not forward the alarm.
- GIVEN a participant with a recorded absence during the period, WHEN the participant is assigned, THEN the system displays a warning but allows the assignment.
- GIVEN a period that includes a public holiday, WHEN a participant is assigned, THEN the system displays a holiday warning.

---

## 12. Assumptions
1. A participant can only be assigned to one period at a time within the same region.
2. The warning for differing participants is informational and does not block saving.
3. Absence warnings are visual indicators only and do not prevent assignment.

# US-03: Assign Escalation On-call Participant

## 1. Requirement Title
Configure escalation on-call participants at the period and region levels to ensure alarm delivery when the regular participant is unreachable.

---

## 2. Business Objective
- **Business Need:** Critical infrastructure alarms must always reach a responsible person. If the primary on-call participant cannot be reached, the system must automatically escalate to backup personnel.
- **Value Delivered:** Guarantees alarm delivery continuity and reduces the risk of unattended critical alarms.
- **Why It Exists:** The F24 eCall interface provides delivery status feedback. When delivery fails, the system must know who to contact next.

---

## 3. Detailed Requirement Description

### Confirmed Requirements
- Escalation follows a defined chain: regular participant → period-level escalation participant → region-level escalation participant.
- An on-call planner can assign an escalation participant at the period level.
- An administrator can assign an escalation participant at the region level.
- Escalation is triggered when the F24 eCall response indicates the regular participant could not be reached.
- The escalation participant must be a configured on-call participant with active alarm media.

### Assumptions
- Only one escalation participant can be assigned per level (period and region).
- The escalation participant is different from the regular on-call participant.

### Not Specified
- The exact eCall response codes that trigger escalation.
- Whether there can be more than one level of escalation beyond region level.
- Timeout duration before escalation is triggered.

---

## 4. User Story

**As an** on-call planner / administrator  
**I want** to assign escalation on-call participants at the period and region levels  
**So that** alarms are automatically forwarded to a backup person when the regular on-call participant cannot be reached

---

## 5. Functional Scope
- Assign an escalation on-call participant at the period level
- Assign an escalation on-call participant at the region level
- System follows escalation chain: regular → period escalation → region escalation
- Escalation triggered based on F24 eCall delivery response
- Display escalation participant information in planning and configuration views

---

## 6. Out of Scope
- F24 eCall interface configuration
- Alarm delay and shipping delay configuration
- Modification of the escalation chain order
- Notification content customization

---

## 7. Preconditions
- At least two on-call participants must be configured in the system (regular and escalation).
- A basic plan with assigned periods must exist.
- On-call regions must be configured.
- The user must have appropriate authorization (planner for period-level, administrator for region-level).

---

## 8. Trigger
- **Period-level:** On-call planner selects a period in the Planning View and assigns an escalation participant.
- **Region-level:** Administrator navigates to Configuration View → On-call Region and assigns an escalation participant.

---

## 9. Main Success Flow

### Period-Level Escalation
1. On-call planner opens the Planning View and selects a period.
2. On-call planner assigns an escalation on-call participant for the period.
3. System saves the escalation assignment.

### Region-Level Escalation
4. Administrator opens the Configuration View and selects an on-call region.
5. Administrator assigns an escalation on-call participant for the region.
6. System saves the escalation assignment.

### Escalation Execution
7. An alarm occurs and is sent to the regular on-call participant via F24 eCall.
8. F24 eCall returns a response indicating the participant could not be reached.
9. System escalates to the period-level escalation participant.
10. If the period-level escalation participant also cannot be reached, system escalates to the region-level escalation participant.

---

## 10. Alternate Flows

### AF-01: Escalation Participant Same as Regular
- The escalation participant is set to the same person as the regular on-call participant.
- **Expected:** System may allow this but it defeats the purpose of escalation. **Not specified** whether the system validates or warns.

### AF-02: No Escalation Participant Configured
- No escalation participant is assigned at either level.
- **Expected:** If the regular participant cannot be reached, the alarm is not forwarded further. The alarm status reflects failed delivery.

### AF-03: Escalation Participant Unreachable
- All participants in the escalation chain are unreachable.
- **Expected:** The alarm remains in the system with a failed delivery status. No further automatic escalation occurs.

### AF-04: Period-Level Escalation Not Set, Region-Level Set
- No period-level escalation participant exists, but a region-level one is configured.
- **Expected:** System skips period-level and escalates directly to region-level escalation participant.

---

## 11. Acceptance Criteria

- GIVEN a period with a regular on-call participant, WHEN an escalation participant is assigned at the period level, THEN the escalation participant is saved and visible in the period details.
- GIVEN a region, WHEN an escalation participant is assigned at the region level, THEN the escalation participant is saved and visible in the region configuration.
- GIVEN a regular participant who cannot be reached (based on eCall response), WHEN escalation is triggered, THEN the system sends the alarm to the period-level escalation participant.
- GIVEN a period-level escalation participant who also cannot be reached, WHEN further escalation is triggered, THEN the system sends the alarm to the region-level escalation participant.
- GIVEN no escalation participants are configured, WHEN the regular participant cannot be reached, THEN the alarm delivery status reflects failure and no further forwarding occurs.
- System must follow the escalation chain order: regular → period escalation → region escalation.

---

## 12. Assumptions
1. Only one escalation participant can be assigned per escalation level.
2. Escalation is triggered automatically based on F24 eCall delivery response.
3. The escalation participant must have at least one active alarm medium.
4. Escalation does not loop — it is a single-pass chain.

# US-04: Manage Duty Period Operations (Split, Merge, Handover) with Participant Assignment

## 1. Requirement Title
Split, merge, and adjust handover times of on-call duty periods while maintaining correct participant assignments.

---

## 2. Business Objective
- **Business Need:** On-call schedules must be flexible to accommodate changes in personnel availability, shift adjustments, and operational needs. Planners need the ability to restructure duty periods without losing assignment integrity.
- **Value Delivered:** Enables dynamic schedule management, reducing planning overhead and ensuring accurate on-call coverage.
- **Why It Exists:** Standard one-week periods may not always fit real-world scheduling needs; split, merge, and handover adjustments provide the required flexibility.

---

## 3. Detailed Requirement Description

### Confirmed Requirements
- **Split:** A period can be split into two parts with a configurable day count. The planner must assign on-call participants to both new periods.
- **Merge:** Two adjacent periods can be merged into one. The planner selects which on-call participant is assigned to the merged period.
- **Handover Adjustment:** The handover time between two periods can be adjusted. The planner confirms the responsible participant for each period.
- A warning is displayed when the assigned participant differs from the originally planned participant after any of these operations.

### Assumptions
- Split, merge, and handover operations are only available within an existing basic plan.
- Only adjacent periods within the same basic plan can be merged.

### Not Specified
- Whether a period of exactly one day can be further split.
- Whether undo functionality is available for split/merge operations.

---

## 4. User Story

**As an** on-call planner  
**I want** to split, merge, and adjust handover times of duty periods and assign on-call participants to the resulting periods  
**So that** on-call schedules can be flexibly managed while maintaining correct personnel assignments

---

## 5. Functional Scope
- Split an existing period into two periods with configurable day count
- Assign on-call participants to both resulting periods after a split
- Merge two adjacent periods into one period
- Select the on-call participant for the merged period
- Adjust handover time between two adjacent periods
- Assign responsible on-call participants after handover adjustment
- Display warning when assigned participant differs from planned participant

---

## 6. Out of Scope
- Creation or deletion of basic plans
- Escalation configuration during period operations
- Alarm forwarding logic during period transitions
- Report generation for modified periods

---

## 7. Preconditions
- A basic plan with at least one period must exist.
- On-call participants must be configured in the system.
- The on-call planner must have appropriate authorization rights.

---

## 8. Trigger
- On-call planner right-clicks or selects a period in the Planning View and chooses Split, Merge, or Adjust Handover.

---

## 9. Main Success Flow

### Split Period
1. On-call planner selects a period and chooses "Split."
2. System prompts for the day count for the split.
3. On-call planner enters the day count.
4. System creates two new periods from the original.
5. On-call planner assigns an on-call participant to each new period.
6. System saves the split periods with their assignments.

### Merge Periods
7. On-call planner selects two adjacent periods and chooses "Merge."
8. System merges the periods into one.
9. On-call planner selects the on-call participant for the merged period.
10. System saves the merged period with the assignment.

### Adjust Handover
11. On-call planner selects a handover point between two periods and chooses "Adjust Transfer Date."
12. On-call planner sets the new handover time.
13. System adjusts the boundary between the two periods.
14. On-call planner confirms the responsible participant for each period.
15. System saves the adjusted periods.

---

## 10. Alternate Flows

### AF-01: Single-Day Period Split
- On-call planner attempts to split a period that is only one day long.
- **Expected:** System may prevent the split or allow it if sub-day periods are supported. **Not specified.**

### AF-02: Merge Non-Adjacent Periods
- On-call planner attempts to merge periods that are not adjacent.
- **Expected:** System does not allow the merge.

### AF-03: Handover Crossing Midnight
- On-call planner adjusts the handover time to cross midnight.
- **Expected:** System allows the adjustment. The participant for each period is responsible for their respective time range.

### AF-04: Participant Differs After Operation
- After split, merge, or handover adjustment, the assigned participant differs from the originally planned participant.
- **Expected:** System displays a warning. The operation is still saved.

---

## 11. Acceptance Criteria

- GIVEN a period within a basic plan, WHEN the on-call planner splits it with a valid day count, THEN two new periods are created and participants can be assigned to each.
- GIVEN two adjacent periods, WHEN the on-call planner merges them, THEN a single period is created and the planner can select the participant.
- GIVEN two adjacent periods, WHEN the on-call planner adjusts the handover time, THEN the period boundaries are updated and participants can be confirmed.
- GIVEN a split, merge, or handover operation, WHEN the assigned participant differs from the planned participant, THEN the system displays a warning.
- System must not allow merging non-adjacent periods.
- After any period operation, the updated assignments must be visible in the Planning View and reflected in evaluation reports.

---

## 12. Assumptions
1. Split and merge operations are reversible by performing the opposite operation.
2. Handover time adjustments affect both adjacent periods simultaneously.
3. Period operations do not affect already-sent alarm messages.

# US-05: View On-call Assignment Reports and Detect Conflicts

## 1. Requirement Title
Generate evaluation reports showing on-call participant assignments across regions and detect scheduling conflicts.

---

## 2. Business Objective
- **Business Need:** Managers and planners need visibility into who is assigned to on-call duty, when, and for which region. They also need to identify conflicts (e.g., unassigned periods, double assignments) to ensure reliable coverage.
- **Value Delivered:** Provides oversight of the entire on-call schedule, enabling proactive conflict resolution and compliance reporting.
- **Why It Exists:** Without centralized reporting, scheduling gaps and overlaps may go undetected, leading to missed alarms or unnecessary burden on individual participants.

---

## 3. Detailed Requirement Description

### Confirmed Requirements
- **Overall Planning Report:** Day-based view of all regions and assigned on-call participants.
- **On-call Region Report:** Duty roster for a selected region and date range.
- **On-call Participant Report:** All assignments for a selected participant.
- Conflicts are highlighted in red.
- Multiple on-call shifts for the same participant are highlighted in orange.
- Reports can be exported as CSV and XML.

### Assumptions
- Reports are read-only views — assignments cannot be modified from the report screen.
- Reports reflect the latest saved assignment data.

### Not Specified
- Whether reports can be scheduled for automatic generation.
- Whether reports include escalation participant information.
- Whether reports show historical data for past completed periods.

---

## 4. User Story

**As a** user (planner/administrator/manager)  
**I want** to generate evaluation reports of on-call participant assignments and see scheduling conflicts highlighted  
**So that** I can verify complete and conflict-free on-call coverage across all regions

---

## 5. Functional Scope
- Generate overall planning report (all regions, day-based view)
- Generate on-call region report (selected region, date range)
- Generate on-call participant report (selected participant)
- Highlight conflicts in red
- Highlight multiple on-call shifts in orange
- Export reports as CSV
- Export reports as XML

---

## 6. Out of Scope
- Modifying assignments from the report view
- Alarm history reporting
- SMS/pager delivery status reporting
- Automated scheduled report generation

---

## 7. Preconditions
- At least one basic plan with assigned participants must exist.
- The user must have authorization to access the Evaluation View.

---

## 8. Trigger
- User navigates to the Evaluation View and selects a report type (Overall Planning, On-call Region, or On-call Participant).

---

## 9. Main Success Flow
1. User opens the Evaluation View.
2. User selects the desired report type.
3. For region or participant reports, the user selects the specific region or participant and date range.
4. System generates the report showing assigned participants per period.
5. System highlights scheduling conflicts in red.
6. System highlights multiple assignments for the same participant in orange.
7. User reviews the report.
8. User optionally exports the report as CSV or XML.

---

## 10. Alternate Flows

### AF-01: No Data for Selected Range
- The user selects a date range or region with no assigned periods.
- **Expected:** System displays an empty report or a message indicating no data is available.

### AF-02: Conflicts Detected
- The report identifies periods without assigned participants or overlapping assignments.
- **Expected:** Conflicts are clearly highlighted in red. The user can navigate to the Planning View to resolve them (via separate functionality).

### AF-03: Export Failure
- The CSV or XML export fails (e.g., file system issue).
- **Expected:** System displays an error message. **Not specified** in detail.

---

## 11. Acceptance Criteria

- GIVEN the Evaluation View, WHEN the user selects "Overall Planning," THEN a day-based report of all regions and assigned participants is displayed.
- GIVEN the Evaluation View, WHEN the user selects a specific region and date range, THEN the on-call region duty roster is displayed.
- GIVEN the Evaluation View, WHEN the user selects a specific participant, THEN all on-call assignments for that participant are displayed.
- GIVEN a report with scheduling conflicts, WHEN the report is rendered, THEN conflicts are highlighted in red.
- GIVEN a report where a participant has multiple on-call shifts, WHEN the report is rendered, THEN those shifts are highlighted in orange.
- GIVEN a generated report, WHEN the user clicks Export as CSV, THEN the report is downloaded in CSV format.
- GIVEN a generated report, WHEN the user clicks Export as XML, THEN the report is downloaded in XML format.

---

## 12. Assumptions
1. Reports are generated on demand and reflect the latest saved data.
2. Color coding (red for conflicts, orange for multiple shifts) is consistent across all report types.
3. Export formats include all visible data columns from the report.
4. All authenticated users with Evaluation View access can generate reports.
